Easy Publish 0.1.5 修正视频账号登录流程，并保留 0.1.4 的应用内存储方式：不访问系统钥匙串，也不读取个人浏览器资料。

## 修复

- 对照 social-auto-upload 的登录、检查和上传流程，优先验证并复用 Easy Publish 已保存的会话；需要重新登录时再打开浏览器。
- 将抖音、小红书和视频号的登录状态与视频上传控件分开判断，并处理扫码后打开的新标签页；空白页和平台验证提示不会被当作登录成功。
- 增加连接阶段提示和“取消连接”；取消会关闭该账号的工作进程并清理临时目录，保留账号及已保存会话。
- 发布流程在新建 Release 草稿后等待短暂的可见性同步，保留来源和附件校验。

完全退出旧版后替换应用，保留原应用数据目录。0.1.4 已连接的账号继续复用应用内会话；从 0.1.3 或更早版本升级时，旧账号需要重新连接，公众号凭据需重新填写，稿件及发布记录保留。校验值见附件 `SHA256SUMS.txt`。

上游 CLI 同样通过浏览器执行这些平台的登录与投稿。本版本对齐其会话复用和登录流程，仍使用 Easy Publish 的任务监督与单次提交保护，并非直接执行整个上游 CLI。

## 验证

验证结果与产物来源在构建完成后记录。开发验证使用隔离页面和 HTTP 数据，不能替代用户实际账号、平台验证或 M5 环境验收。

系统要求为 macOS 13.5+／Windows 10+ x64。签名方式沿用此前版本：macOS ad-hoc 完整性签名，尚未进行 Developer ID 公证；Windows 未配置商业代码签名。
