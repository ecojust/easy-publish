### A6 · 收尾回归及用户实际 Mac 启动问题

- 收尾提交 [c33f168](https://github.com/ecojust/easy-publish/commit/c33f168313153931c43073d714ef40b9472b4eb7)（`fix: clean browser profiles and speed up UI checks`）已推送；[CI 42241437559](https://github.com/ecojust/easy-publish/actions/runs/42241437559) 的 UI job 成功，Windows 和 Intel 的引擎测试失败，ARM 尚在排队。正在核对新增临时目录断言在 macOS `/var` 与 `/private/var`、Windows 路径规范化下的差异，未把推测写成已确认原因。
- 用户反馈 macOS 26.5 的 M5 电脑几乎立即出现引擎启动失败；首轮 CI 的原生启动 smoke 不能代表这台用户设备的验收。当前任务转为修复该实际启动问题，同时保留文章／视频桌面发布器目标。
- 已分工检查原生启动时被丢弃的 stderr／退出码，以及 Mac 冻结引擎的依赖和签名；将补上可诊断的错误信息，避免只提示重启。
- 请求用户运行使用独立临时目录的引擎启动诊断命令，stdout 重定向到 `/dev/null`，不收集启动 token 或发布任何内容；等待实际报错文本。
- 用户说明问题弹窗无法复制命令后，改在普通对话中直接提供同一条命令。用户返回的错误明确为 **mapping process and mapped file … have different Team IDs**，确认是打包签名与 hardened runtime 的库校验冲突，不能继续归因于需要重启或缺少 Python。
- 查明 PyInstaller 6.22.3 中显式 `--codesign-identity '-'` 会启用 `--options=runtime`；Tauri 默认也启用 hardened runtime。当前构建没有 Developer ID 团队签名，Python 库因此被用户 Mac 拒绝加载。修复计划为正确的 ad-hoc 签名模式：PyInstaller 使用默认 ad-hoc，Tauri 显式关闭该构建的 hardened runtime；保留严格签名完整性检查，并加入签名标志回归检查。
- 版本更新为 0.1.1，以便区分修复安装包与 0.1.0；同时增加启动 stderr／退出码的安全诊断与复制入口。此处只是修复进行中，尚未在用户 M5 电脑确认成功。
- CI 42241437559 完成后成功取得整轮失败日志（临时路径 `/tmp/easy-publish-ci2-failed.log`）：三个目标均为新增两个临时 profile 测试超时，其他 **117 passed**。用 symlink 临时目录在 Linux 复现该断言路径问题，规范化 fixture 路径后同样环境下 **19 runtime tests passed**；生产运行时路径不作回退。

### A7 · 0.1.1 签名修复与诊断验证

- PyInstaller 改为默认 ad-hoc 签名，去掉显式 `--codesign-identity '-'`；Tauri 配置 `macOS.hardenedRuntime: false`。保持本地测试构建身份，没有声称 Developer ID 或 Apple 公证。
- 新增 `scripts/check-macos-signature.py`：不仅验证签名完整性，还验证 ad-hoc 身份且 `CS_RUNTIME` 位未启用；构建出的独立引擎和最终应用／sidecar 都需要通过。
- Mac CI 改为挂载生成的 DMG、复制 `.app` 后检查签名，再使用精简环境运行独立引擎及原生宿主启动 smoke，更贴近安装后的启动路径。
- 原生宿主新增 `startup.rs`：仅保留启动握手前最多 16 KiB 的 stderr，记录退出状态并显示诊断位置；不记录 stdout 握手或 token，对潜在凭据行和 home 路径脱敏。日志文件权限 0600、目录 0700，不新增剪贴板依赖。
- 统一应用／引擎／构建产物版本为 0.1.1。完整引擎测试 **119 passed**（5.72 秒），Rust **9 passed**；完整原生 `cargo check`、格式、Python compile、actionlint 及 diff 检查通过。签名检查脚本的隔离 fixtures 接受正常 ad-hoc、拒绝 runtime 标志或缺失签名元数据。
- 根据 Apple codesign 手册与 CodeSigner 源码核实 `--options 0` 的语义，在普通对话中给出仅重新签名已安装应用（先 sidecar、再外层 app）的临时恢复命令。尚未收到用户运行结果；未要求关闭系统安全保护，也未将源码核实描述成在本机 Mac 上执行过。
