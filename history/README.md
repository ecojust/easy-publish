# 用户请求与行动记录

本目录帮助后续 agent 从可复查的状态继续工作。先读 [INDEX.md](INDEX.md)，再打开最新记录及与任务相关的未完成记录，同时核对实际 Git 状态和仓库文件。

## 记录规则

- 文件名为 `YYYY-MM-DD-NNN.md`，日期采用 UTC，序号从 `001` 递增。同一持续任务可以跨日期追加；独立新任务创建新文件并登记索引。
- 用户 prompt 原样记录并编号，保留补充顺序。无法取得的历史原文明示“原文不可得”，不得编造；秘密使用 `[已脱敏：类型]` 替换并注明。
- 有意义的阶段后追加行动条目，说明实际动作、文件、验证、证据、结果和限制。发现判断有误时追加更正，保留原始过程。
- 状态使用 `in_progress`、`blocked`、`completed`、`cancelled`。`blocked` 写明具体缺项；只有本条请求的目标已完成才标记 `completed`。等待用户提出新的独立任务，不妨碍将已完成的当前任务标为 `completed`。
- 仓库文件使用相对链接；提交、PR 和工作流使用完整链接。临时绝对路径应标注“临时，后续环境可能不存在”，不能作为唯一证据。
- 区分计划执行、执行中、失败、通过和未验证；测试计数取自真实输出。源码修改、远端推送、合并与发布分别说明。
- 不保存秘密、完整敏感输出或私有推理。记录简短结论与依据，详细持久报告按后续实际项目目录存放并链接。
- 多 agent 协作由主 agent 汇总日志与索引，避免同时修改同一段记录。
- 每个有意义的阶段后及最终回复前同步更新索引，至少写明状态、用户目标、当前结果和下一步。

## 模板

```markdown
# YYYY-MM-DD · 任务名称

- 状态：in_progress
- 分支：实际分支
- 起点：实际提交 SHA
- 关联记录：无／相对链接
- 当前目标与边界：用户要求及本次实际范围

## 用户 prompt

### U1

> 可见用户原话；无法取得的历史原文明示不可得

## 行动记录

### A1 · 阶段名称

- 动作与文件：实际做了什么。
- 决策摘要：采用方案的可复查依据。
- 验证与结果：执行过的检查、退出结果和必要计数。
- 证据：仓库链接、提交或工作流；临时路径注明可能失效。
- 限制与未完成：准确说明未执行或待办事项。

## 当前交接

- 已完成：已核实结果。
- 正在进行／阻塞：准确状态及缺项。
- 下一步：下一项已授权动作，或用户明确要求的等待边界。
- 提交与发布状态：已提交／已推送／已合并／已发布分别记录。
```
